# UC-001 – Add Athlete

**Status:** Approved  
**Version:** 1.0  
**Module:** Athlete  
**Priority:** High

## 1. Goal

Allow the coach to add a new athlete to the TFHub system.

After successful creation, the athlete is stored in the database and becomes available in the list of active athletes.

## 2. Actor

- Coach – the only system user at the current stage of development.

## 3. Preconditions

- The backend application is running.
- The database is available.

## 4. Input Data

The user provides exactly four fields:

| Field | Type | Required |
|---|---|---|
| firstName | String | Yes |
| lastName | String | Yes |
| birthYear | Integer | Yes |
| gender | Gender enum | Yes |

Allowed `gender` values:
- `MALE`
- `FEMALE`

## 5. Main Flow

1. The coach starts the athlete creation process.
2. The system provides a form with four required fields.
3. The coach enters the first name, last name, birth year, and gender.
4. The system trims leading and trailing whitespace from the first name and last name.
5. The system validates the input data.
6. The system checks whether an athlete with the same first name, last name, and birth year already exists.
7. The system saves the athlete to the database.
8. The system returns the created athlete's data.

## 6. Validation Rules

### First Name and Last Name
- Both fields are required.
- After trimming, neither field can be empty.
- Maximum length of each field is 100 characters.
- The system does not change letter casing or modify the remaining field content.

### Birth Year
- Required.
- Must be an integer.
- Minimum value: 1900.
- Maximum value: the current calendar year.
- The current year must be determined and validated on the backend.

### Gender
- Required.
- Only `MALE` and `FEMALE` values are allowed.

### Duplicate Prevention
- An athlete with the same first name, last name, and birth year cannot be created more than once.
- Duplicate detection is performed after trimming the input values.
- The database UNIQUE constraint provides the final protection against duplicates.

## 7. Automatically Assigned Values

The system assigns:
- `id` – generated by the database.
- `active` – set to `true`.

The user must not be able to provide these values in the creation request.

## 8. Alternative Flows and Error Handling

| Scenario | Expected Behavior |
|---|---|
| First name is missing | Reject the request with a validation error |
| Last name is missing | Reject the request with a validation error |
| First name or last name is empty after trimming | Reject the request |
| First name or last name exceeds 100 characters | Reject the request |
| Birth year is earlier than 1900 | Reject the request |
| Birth year is later than the current year | Reject the request |
| Birth year is not an integer | Reject the request |
| Invalid gender value | Reject the request |
| Athlete already exists | Reject the request and report a duplicate |
| Database persistence error | Return an appropriate error without partially creating the athlete |

## 9. API

**Endpoint:**

`POST /api/athletes`

Example request:

```json
{
  "firstName": "John",
  "lastName": "Smith",
  "birthYear": 2010,
  "gender": "MALE"
}
```

Expected successful response:
- HTTP `201 Created`
- Return the created athlete as a response DTO.
- Include a `Location` header pointing to the newly created resource.

Example response:

```json
{
  "id": 1,
  "firstName": "John",
  "lastName": "Smith",
  "birthYear": 2010,
  "gender": "MALE",
  "active": true
}
```

Expected error status codes:
- HTTP `400 Bad Request` – invalid input data.
- HTTP `409 Conflict` – an athlete with the provided identifying data already exists.

Errors must follow the application's standardized error response format.

## 10. Acceptance Criteria

- [ ] An athlete can be created using valid input data.
- [ ] The athlete is persisted in the database.
- [ ] The ID is generated automatically.
- [ ] A newly created athlete has `active = true`.
- [ ] First name and last name are trimmed.
- [ ] Values that are empty after trimming are rejected.
- [ ] First name and last name cannot exceed 100 characters.
- [ ] Birth year cannot be earlier than 1900.
- [ ] Birth year cannot be later than the current year.
- [ ] Only `MALE` and `FEMALE` gender values are accepted.
- [ ] Duplicate athletes cannot be created.
- [ ] Successful creation returns HTTP 201 and the athlete DTO.
- [ ] Validation errors return HTTP 400.
- [ ] Duplicate creation attempts return HTTP 409.
- [ ] Athlete creation and validation logic are covered by tests.

## 11. Out of Scope

- Updating an athlete.
- Deactivating an athlete.
- Deleting an athlete.
- Displaying the athlete list.
- Searching and filtering athletes.
- Multi-user and authorization support.
